# Spec: Bulk service import (CSV / Excel) on the customer Services tab

**Status:** Draft — awaiting approval · **Date:** 2026-10-31 · **Branch:** `feat/crm-improvements`

## 1. Problem

Creating services for a customer is one-at-a-time: open the dialog, fill up to 12 fields, save, repeat; sub-services need a separate "add sub-service" action per parent. Customers with many lines (e.g. a 5G plan with 10 extra cards) take dozens of dialog round-trips.

## 2. Goal

From a customer's **Services tab** (`/customers/:id` → Serviços), a user can:

1. Download a template (**CSV or Excel**) with basic instructions and examples.
2. Fill it in Excel with any number of services **and their sub-services**.
3. Upload it, see a **preview** with every problem highlighted per row/field.
4. When the file has no errors, save everything in **one click, all-or-nothing**.

### Decisions (agreed 2026-10-31)

| Topic | Decision |
|---|---|
| Parent link | `ref` + `pai` columns. `pai` = a `ref` in the same file, **or** the Acesso of a service the customer already has. Row order is irrelevant. |
| Errors | Preview first; nothing is saved while any row has an error; save is a single transaction. |
| Formats | CSV **and** Excel (.xlsx), both for the template and the upload. |
| Required fields | **Acesso, Operadora, Valor** only. Conta and CVP become optional everywhere (CSV, form, model). |

### Out of scope (for now)

- Cross-customer import (a `cliente`/NIF column, from the Services page). The parser is designed so it can be added later.
- Updating or deleting existing services via file — import only **creates**.
- Editing cells inside the preview — the user fixes the file and re-uploads.

## 3. The file

### Columns

Headers are matched case-insensitively, ignoring accents, spaces and `_`/`-` (`Nº Serviço`, `num_servico`, `Numero servico` all match). Column order is free. Unknown columns → warning, ignored.

| Column | Req. | Maps to | Rules |
|---|---|---|---|
| `ref` | | — | Free short label (e.g. `P1`), unique in the file. Only needed on rows that have children in the file. |
| `pai` | | `parent` | A `ref` from this file, or the Acesso of an existing **main** service of this customer. Empty = main service. |
| `acesso` | ✔ | `acesso` | ≤ 100 chars. |
| `operadora` | ✔ | `operadora` | ≤ 100 chars. Free text (MEO, NOS, Vodafone…). |
| `valor` | ✔ | `valor` | ≥ 0, max 2 decimals. Accepts `12,50`, `12.50`, `1.234,56`, `€ 12,50`, Excel numeric cells. |
| `tarifario` | | `tarifario` | ≤ 100 chars. |
| `conta` | | `conta` | ≤ 100 chars. |
| `cvp` | | `cvp` | ≤ 100 chars. |
| `data_fim` | | `data_fim` | `DD/MM/AAAA`, `AAAA-MM-DD`, or an Excel date cell. |
| `num_cliente` | | `num_client` | ≤ 100 chars. |
| `num_servico` | | `num_servico` | ≤ 100 chars. |
| `morada` | | `morada` | Free text. |
| `observacoes` | | `observacoes` | Free text. |

`moeda` is not a column (EUR only today). Values are trimmed; fully empty rows are skipped.

### Example

```
ref;pai;acesso;operadora;tarifario;valor;conta;cvp;data_fim;num_cliente;num_servico;morada;observacoes
P1;;912000001;MEO;Empresas 5G;25,00;C-1001;;31/12/2027;;;;Plano principal
;P1;912000002;MEO;Cartão adicional;5,00;;;31/12/2027;;;;
;P1;912000003;MEO;Cartão adicional;5,00;;;31/12/2027;;;;
;911555000;912000004;MEO;Cartão adicional;0,00;;;;;;;Filho de um serviço já existente
;;253000111;NOS;Fibra 1Gbps;32,90;;;15/06/2027;;;Rua X 12, Braga;
```

### Templates

Generated by the backend (single source of truth for the columns):

- **Excel** (`servicos-modelo.xlsx`): sheet **Serviços** (styled header, required columns marked `*`, 3 example rows, `data_fim` column date-formatted, `valor` number-formatted) and sheet **Instruções** (the rules above in Portuguese).
- **CSV** (`servicos-modelo.csv`): UTF-8 with BOM, `;` separator (what pt-PT Excel opens correctly), header + the same example rows.
- Example rows use Acesso `EXEMPLO-1`… and are **rejected on upload** with "Remova as linhas de exemplo antes de importar" so they're never imported by accident.

### Instructions shown to the user (dialog + Instruções sheet)

1. Uma linha por serviço. Obrigatórios: Acesso, Operadora, Valor.
2. Para criar sub-serviços, dê um `ref` ao serviço principal (ex.: P1) e escreva esse `ref` na coluna `pai` de cada sub-serviço.
3. Para acrescentar sub-serviços a um serviço que o cliente já tem, escreva o Acesso desse serviço na coluna `pai`.
4. Um sub-serviço não pode ter sub-serviços.
5. Valor com vírgula ou ponto (12,50). Data de fim em DD/MM/AAAA.
6. Apague as linhas de exemplo antes de importar.

## 4. Parsing

- **Size limits:** ≤ 2 MB and ≤ 500 data rows (file-level error otherwise).
- **Type detection** by extension + content sniff: `.xlsx` → openpyxl (first sheet, or the sheet named `Serviços` if present; `read_only`, `data_only`). `.csv`/`.txt` → csv module.
- **CSV encoding:** `utf-8-sig`; on decode failure fall back to `cp1252` (Excel "CSV" on Windows).
- **CSV delimiter:** `csv.Sniffer` restricted to `;`, `,`, `\t`; default `;`.
- Row numbers reported to the user are the **spreadsheet row numbers** (header = row 1).

## 5. Validation

Two levels; the preview shows both. **Errors block saving; warnings don't.**

**File-level errors:** unreadable/unsupported file, empty file, missing required column(s), too many rows/too large.

**Row errors** (each tied to a field):
- Required field empty; value too long; `valor` not a number / negative / > 2 decimals; `data_fim` not a valid date.
- `ref` duplicated in the file.
- `pai` resolves to nothing (neither a `ref` in the file nor an existing service's Acesso).
- `pai` points to a row/service that is itself a sub-service (max 1 level).
- `pai` matches more than one existing main service by Acesso (ambiguous — ask the user to fix the data).
- `pai` points to its own row.
- Example row (`EXEMPLO-…`) still present.

**Row warnings:**
- Acesso already exists for this customer (possible duplicate).
- Same Acesso appears more than once in the file.
- `data_fim` in the past.
- Unknown columns (file-level warning).

Resolution order for `pai`: first a `ref` in the file, then an existing service's Acesso. A `ref` in the file shadows an existing Acesso with the same text (documented).

## 6. API

Both endpoints are nested under the customer, same auth as the rest of the API (session + CSRF).

### `GET /api/customers/{id}/services/import-template/?format=xlsx|csv`
Returns the file as an attachment (`Content-Disposition`). Default `xlsx`.

### `POST /api/customers/{id}/services/import/` (multipart, field `file`)
Query `?dry_run=1` → validate only. Without it → validate again and, if there are no errors, create everything in one `transaction.atomic()`. The client simply re-sends the same file on confirm (stateless — no server-side upload storage).

Response (both modes, `200` when the file could be read; `400` only for file-level errors):

```json
{
  "dry_run": true,
  "summary": { "rows": 5, "main": 2, "children": 3, "errors": 0, "warnings": 1 },
  "file_errors": [],
  "file_warnings": ["Coluna desconhecida ignorada: «extra»"],
  "rows": [
    {
      "row": 2, "ref": "P1", "pai": "",
      "parent_type": null,
      "values": { "acesso": "912000001", "operadora": "MEO", "valor": "25.00", "data_fim": "2027-12-31", "...": "" },
      "errors": [],
      "warnings": [{ "field": "acesso", "message": "Já existe um serviço com este Acesso neste cliente." }]
    }
  ],
  "created": null
}
```

`parent_type`: `null` (main), `"file"` (parent is a row in this file) or `"existing"` (with `parent_id`). On a successful commit `created` is `{ "main": 2, "children": 3 }`; if errors exist, commit returns the same report with `created: null` and status `400` and writes nothing.

## 7. Backend design

- `apps/services/bulk_import/`:
  - `columns.py` — column definitions (key, header label, required, max length, model field) + header normalisation. Used by parser, validator **and** template, so they can't drift.
  - `parser.py` — bytes + filename → list of `(row_number, {key: raw_value})`, file errors/warnings.
  - `validator.py` — raw rows + customer → typed rows, per-field errors/warnings, resolved parents.
  - `template.py` — builds the CSV and the xlsx (openpyxl).
  - `service.py` — `import_services(customer, file, dry_run)` orchestrating the above; commit creates main services first, then children, inside one transaction (model `full_clean()` still runs on save). Create rows with `.save()`/`.create()` (not `bulk_create`) so the `post_save` signal registers each tarifário in the `Tarifario` table — or call `register_tarifario` explicitly if switching to `bulk_create`.
- Views: two `@action`s on `CustomerServiceViewSet` (`import`, `import-template`), or a small `APIView` pair — whichever keeps the router simplest.
- **Model change:** `CustomerService.conta` and `.cvp` → `blank=True, default=''` (+ migration, no data change). Serializers follow. Frontend form: drop `required` on Conta/CVP.
- **Dependency:** `openpyxl` → `requirements.txt` (and `pyproject.toml`). `deploy-backend.sh` already runs `pip install -r requirements.txt`.

## 8. Frontend design

In `CustomerServicesTab`, next to **Adicionar serviço**, a secondary button **Importar** (`Upload` icon) opens `CustomerServicesImportDialog` (wide dialog, two steps):

**Step 1 — Ficheiro**
- Short instructions (the 6 points, collapsible after first view).
- "Descarregar modelo": **Excel** (primary) · CSV.
- `FileDropZone` (already in `components/ui/`) accepting `.xlsx,.csv`. On drop → `dry_run` request → step 2. File-level errors shown inline here.

**Step 2 — Pré-visualização**
- Summary strip: N serviços principais · N sub-serviços · N erros · N avisos.
- Table: row nº, hierarchy (children indented with ↳ under their file parent; "↳ existente: 911555000" for existing parents), Acesso, Operadora, Tarifário, Valor, Data fim, then status. Cells with an error get the error tone and the message beneath/tooltip; warnings use the warning tone. Rows with errors sorted first? **No** — keep file order so it matches the spreadsheet; offer a "Mostrar só linhas com problemas" toggle.
- Footer: **Escolher outro ficheiro** (back to step 1) · **Importar N serviços** (disabled while errors > 0; shows "Corrija os erros no ficheiro e carregue-o de novo").
- On success: toast "N serviços importados", close, invalidate `['customer-services', id]`, `['services']`, `['dashboard-summary']`.

API client: `customerServicesApi.importPreview(customerId, file)`, `.importCommit(customerId, file)` (FormData via raw `fetch` + CSRF, like document upload), `.templateUrl(customerId, format)`. Types for the report in `types/index.ts` — mapped by hand (keys like `data_fim` inside `values` should stay as the backend sends them or be mapped explicitly; don't rely on the generic transformer for this payload).

## 9. Testing

Backend (`apps/services/tests_bulk_import.py` or a `tests/` package):
- Parser: `;` and `,` CSVs, UTF-8 BOM, cp1252, blank rows, header aliases/accents, xlsx with numeric and date cells, oversize/too many rows, unsupported type.
- Validator: each error and warning in §5; `pai` → file ref, → existing service, → existing child (error), → ambiguous Acesso, → unknown; 2-level nesting rejected.
- Commit: all-or-nothing (one bad row → nothing created); parents before children; correct `parent_id` for both file and existing parents; dry-run writes nothing.
- Template: CSV and xlsx round-trip — downloading the template, deleting the example rows and uploading parses cleanly; uploading it unchanged flags the example rows.
- Endpoints: auth, 404 for unknown customer, 400 for file errors.

Frontend: `npm run build` + lint; manual run-through with the template on the local legacy data.

## 10. Implementation plan

1. Model: make `conta`/`cvp` optional (migration, serializer, form). Small, independent commit.
2. `columns.py` + `parser.py` + tests.
3. `validator.py` + tests.
4. `service.py` (dry-run + atomic commit) + endpoints + tests.
5. `template.py` (CSV + xlsx) + endpoint + round-trip tests; add `openpyxl`.
6. Frontend: API client + types + hook.
7. Frontend: import dialog (step 1, step 2), wire into the Services tab.
8. Docs: CLAUDE.md (endpoints, new dependency), manual QA with real-shaped files from Excel (pt-PT locale).

## 11. Risks & notes

- **Excel locale quirks** are the main risk (delimiter, decimal comma, dates as text vs. cells, leading zeros dropped from numbers like `0800…` when Excel guesses numeric). Mitigation: xlsx template formats Acesso/Nº columns as **Text**; tests with files saved from pt-PT Excel.
- **Duplicates** are only warned about, never blocked — the same Acesso legitimately appears in legacy data.
- Prod nginx `client_max_body_size` is 27M — no change needed for a 2 MB limit.
- Stateless confirm means the file is parsed twice; at ≤ 500 rows this is negligible.
